# 餐厅翻新 Merge-2 分析口径

优先级：U1

## 数据链路

生成器与能量 → 棋盘物品 → 二合 → 订单 → 金币和星星 → 装修 → 阻塞事件 → IAP 提供与购买。

## 关键事件

| 事件 | 触发 | 分析用途 |
|---|---|---|
| `game_start` | 新档开始 | 初始资源与订单基线 |
| `generated` | 生成成功 | 能量消耗、物品来源 |
| `energy_blocked` | 能量不足 | 检查能量墙是否过早 |
| `board_full` | 棋盘满 | 检查订单与生成比例 |
| `merged` | 二合成功 | 升阶效率与目标等级 |
| `order_completed` | 订单交付 | 金币、星星与订单节奏 |
| `stage_completed` | 装修推进 | 长期目标速度 |
| `iap_offer` | 真实阻塞后提供礼包 | 付费机会质量 |
| `iap_declined` | 模拟玩家拒绝礼包 | 付费漏斗 |
| `iap_purchase` | 模拟购买成功 | 礼包收入与购买次数 |

## 同期观察指标

- 人均订单数。
- 人均二合次数和生成次数。
- 第 14 日平均装修阶段。
- 能量阻塞日与棋盘阻塞日。
- 每名玩家的 IAP 提供数。
- 各分层付费率和人均收入。

## 实验设计

界面并行运行“标准商店”和“低门槛开业包”两套参数。

比较时：

1. 使用相同玩家数和随机种子。
2. 保持订单、生成器、能量和装修参数一致。
3. 只改变开业包价格与内容。
4. 同时比较付费率、ARPPU、装修速度和阻塞日。
5. 不用单次合成结果推导市场结论。

## 解释边界

- 玩家行为由规则机器人代替。
- 付费分层和购买概率是假设。
- 队列没有流失、复访、时区和广告，不是留存模型。
- 可用于作品集展示指标联动，不可当作商业预测。
