# 餐厅翻新 Merge-2 验收与测试计划

优先级：U1

## 功能验收

| 编号 | 场景 | 通过标准 |
|---|---|---|
| M01 | 使用生成器 | 扣能量、减次数、增加一张一级物品 |
| M02 | 同链同等级二合 | 消耗两张，生成下一等级一张 |
| M03 | 不同链或不同等级 | 禁止二合 |
| M04 | 最高等级二合 | 禁止二合 |
| M05 | 订单未满足 | 交付按钮不可用 |
| M06 | 订单满足 | 移除需求物品，发金币和星星 |
| M07 | 达到装修门槛 | 扣金币、保留星星、阶段加一 |
| M08 | 一次性礼包重复购买 | 禁止 |
| M09 | 宝石换能量 | 宝石足够时执行，能量不超过上限 |
| M10 | 推进一天 | 补能量并重置生成器次数 |
| M11 | 导出事件 | CSV 包含事件类型、资源和棋盘状态 |

## 边界验收

- 棋盘满时生成失败且不扣能量。
- 能量不足时不扣生成器次数。
- 生成器每日次数为 0 时不能生成。
- 订单跨多条物品链时，只有全部需求满足才可交付。
- 装修阶段要求必须单调递增。
- 分层玩家 share 必须合计为 1。
- 一次性礼包只能购买一次。

## 回归验收

- 固定 seed 的初始棋盘一致。
- 固定玩家 seed 的 14 天队列结果一致。
- 修改礼包内容不改变生成器和二合规则。
- 修改装修金币要求不影响能量账本。
- 新物品等级连续时，配置校验通过。

## 自动测试

```powershell
python -m unittest discover -s tests -v
```
