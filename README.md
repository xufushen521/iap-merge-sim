# IAP 餐厅翻新 Merge-2

优先级：U1  
更新日期：2026-11-12

一个可玩的餐厅翻新 Merge-2 原型，用生成器、二合升阶、订单、装修和资源礼包验证 IAP 经济链。参考通用机制，不复制任何游戏的 IP、素材、剧情、棋盘或关卡。

[配置工作簿](docs/iap_merge_config.xlsx) · [美术需求](docs/iap_merge_art_requirements.docx) · [合成队列报告](outputs/COHORT_REPORT.md) · [设计复盘](docs/06_ANALYSIS_REVIEW.md)

## 数据范围

- 当前版本不连接真实游戏、支付渠道或线上分析系统，不能直接取得真实线上数据。
- 可以通过分层玩家、日活概率、购买概率和 14 天队列模拟“线上行为数据”。
- 付费率、ARPPU、ARPDAU 与收入均为合成结果，不是真实产品数据或市场预测。
- 事件结构和资源账本可替换为后续真实埋点与支付回传。

## 当前合成结果

固定种子 `20261110`，1200 名虚拟玩家×14 天：

| 指标 | 标准商店 |
|---|---:|
| 合成付费率 | 1.83% |
| ARPPU | $2.40 |
| ARPDAU | $0.0041 |
| 人均订单 | 6.76 |
| 人均二合 | 57.0 |
| 平均装修阶段 | 2.09 |
| 至少完成 3 个装修阶段 | 30.0% |
| 平均能量阻塞日 | 1.95 |
| 平均棋盘阻塞日 | 0.00 |

开业包降价没有提高合成付费率，收入反而下降；当前模型不假设价格与购买概率存在因果关系。

## 启动

双击 `启动试玩.bat`，或在当前目录运行：

```powershell
python -m streamlit run app.py
```

## 重新生成数据

```powershell
python scripts/run_simulation.py --players 1200 --seed 20261110
python -m unittest discover -s tests -v
```

## 数据链路

`能量 → 生成器 → 二合升阶 → 订单 → 金币/星星 → 装修 → 资源阻塞 → IAP 提供/购买 → 分层队列分析`

合成付费率、ARPPU、ARPDAU 与收入全部来自虚拟行为规则，不是真实经营数据。
